# 个人博客与小球养成网站

一个可直接发布的静态个人网站 V1：包含作品集、编辑型博客，以及使用浏览器 `localStorage` 保存进度的小球养成房间。项目不需要框架、数据库、账号、API 密钥或构建步骤。

## 页面清单

- `index.html`：首页，按“身份与方向 → 代表游戏项目 → ZeroHey 运营成果 → 工作范围 → 小球房间”的顺序组织内容；西湖龙井茶 APP 仅保留在完整作品与文章归档中，不作为首页主推项目。
- `works.html`：9 组真实作品以两级档案夹组织并支持分类筛选。第一层展开单个项目，第二层展开项目内的作品章节；图片在章节阅读器中逐张翻阅，避免把全部素材同时铺在页面上。
- `work-detail.html`：仅为已经分享出去的旧链接保留兼容，不再出现在主导航、首页作品入口或 sitemap 中。
- `articles.html`：暂不展示文章，以小球表情包和“欸？空的～”作为空状态。
- `article-detail.html`：保留西湖龙井茶 APP 的旧文章详情文件，当前文章页不提供入口。
- `about.html`：仅为旧地址保留的内容存档，不再出现在主导航或 sitemap 中。
- `pet.html`：领养、命名、四项状态、四种互动、本地存档与二次确认重置。
- `404.html`：迷路小球情境与返回入口。

## 技术与设计说明

- HTML5、CSS3、原生 JavaScript（ES6+），无构建步骤。
- 视觉参考被转译为暖白底、深灰正文与酒红重点色。2026-08 的收敛优化移除了纸纹、旋转标签、异形圆角、多色卡片和重复阴影。背景由 `site.js` 实时绘制为“静态意象锚点 + 三条流动叙事线 + 光点与漂移符号”的关系场景：左下的生长线与右上的悬线彼此呼应，酒红、鼠尾草绿、旧金和墨色与网站主体配色一致；线条、微粒和抽象羽片沿同一轨迹低速流动并轻微响应滚动和鼠标。移动端减少动态对象，标签页失焦时暂停，`prefers-reduced-motion` 下只保留静态帧。没有复制参考作品的文字、星河、人物、具体物件或构图，也没有逐像素临摹。
- 字体完全使用系统字体栈；无 Google Fonts、第三方 CDN 或远程脚本。
- 每个浏览器标签页首次进入网站时显示小球喝水加载动画；页面资源就绪后杯中水位降至空杯，再淡出显示正文。`prefers-reduced-motion` 下跳过持续动画并快速进入页面。
- 作品图片已从用户提供的 `E:\Resume\简历\作品`、`assets/images/FARWORLDBEACON/` 与三个公开 B 站项目页中筛选、复制并进行网页尺寸优化；页面不依赖远程封面加载。
- 三个游戏详情页按用户提供的播放器参数嵌入 B 站视频，播放器使用响应式 16:9 容器与懒加载，并保留 B 站原页链接；视频播放本身需要访问 `player.bilibili.com`。
- ZeroHey 内容运营成果不再设置独立“关于”入口；旧页面内容仅作本地存档，不参与当前网站主导航。
- 首页首屏使用以小球为中心的“作品星系”：五个作品方向入口环绕主体，小红书入口位于下方。小球由无眼睛身体底图与左右两个不对称白眼图层构成；桌面端连续看向光标或聚焦元素的实际位置，方向状态只用于正视动作与触屏端低频自主观察。不添加瞳孔，并兼容 `prefers-reduced-motion`。
- 作品页不设置额外的宣传式头图区，进入页面后直接看到分类与项目目录；页面仍保留仅供辅助技术读取的主标题。项目名称独占一行，简介与标签位于标题下方。
- 作品档案默认全部收起；打开一个项目时会收起其他项目。卡片只用圆形箭头暗示可展开，不显示“几项内容”等统计文案；项目内部章节只保留标题、文件夹符号与折叠箭头。“全部收起”按钮可快速返回项目目录，带项目锚点的链接会自动恢复对应展开状态。
- 项目目录使用双列卡片（窄屏自动单列）。每张卡片最多选取 6 张代表图；鼠标悬停或键盘聚焦图片时显示左右切换按钮，触摸设备始终显示按钮。切换预览不会打开项目，点击卡片其余区域才展开详情。卡片和展开页均使用受约束的展示画布与 `object-fit: contain`，保证横版、竖版和方形作品完整等比显示，不以裁切或拉伸换取统一尺寸。
- 支持精细指针的设备上，作品卡片在进入和离开时会进行一次快速衰减的微振；动效只使用 `transform`，最大旋转约 0.11°、位移不足 1px，不会改变布局。触屏和 `prefers-reduced-motion` 环境不运行该引导动效。
- 所有可复用颜色、间距、圆角、阴影和宽度集中在 `assets/css/tokens.css`。
- 页面间距使用流式 gutter，作品网格采用自适应列数；导航、标题、按钮、滑块和图片在 320px、390px、768px 与宽屏下分别收束，避免横向溢出。
- 支持键盘焦点、跳到主要内容、移动端菜单、`Esc` 关闭菜单和 `prefers-reduced-motion`。
- 全站页脚只保留署名与年份，不重复顶部导航或使用面向维护者的素材说明；返回顶部使用滚动后出现的无文字悬浮圆形按钮。
- 首页避免让多个相同分量的标题争夺注意力：不显示作品数量、维护日期或浏览说明；代表项目优先展示 FARWORLD BEACON、《笔墨山河》和 AnchorStage，ZeroHey 运营成果作为独立重点案例，小球房间作为页面收尾。

## 本地运行

在项目根目录执行：

```bash
python -m http.server 8000
```

然后打开 `http://localhost:8000/`。

不建议把“双击 HTML 文件”作为唯一测试方式：`file://` 与真实静态服务器的路径、缓存、安全策略和 404 行为不同。通过本地 HTTP 服务器预览更接近 GitHub Pages。

## 替换基础信息

编辑 `assets/js/site-config.js`：

- `siteName`：网站名称；
- `ownerName`：姓名或个人品牌；
- `roleLine`、`intro`：身份与简介；
- `email`：公开邮箱；
- `github`、`bilibili`、`jike`、`xiaohongshu`：正式社交链接。

页面里的结构性文案使用 `[请替换：……]` 标记，可全局搜索 `请替换`。替换后同步更新各 HTML 的 `<title>`、description、Open Graph、canonical，以及首页 JSON-LD。

## 添加新作品

1. 在 `works.html` 复制一个 `<article class="work-showcase">` 项目章节。
2. 设置 `data-category` 为 `game`、`product`、`art` 或 `drawing`，使筛选生效。
3. 为章节设置唯一 `id`，首页或文章页使用 `works.html#项目代号` 直接定位，不再创建独立详情页。
4. 同层级图片放进 `.media-rail`；UI 界面或数量较多的统一图板可复用 `data-gallery-slider` 与 `assets/js/gallery-slider.js`。动态展廊一次显示一张，自动淡入切换，支持暂停、按钮、方向键和触摸手势；普通作品图片保持响应式布局。
5. 正式图片放在 `assets/images/works/`，使用相对路径、明确的 `width`、`height`、描述性 `alt` 与首屏外懒加载。

## 添加新文章

1. 在 `articles.html` 复制一个文章卡片。
2. 设置 `data-category` 为 `design`、`review`、`operation` 或 `art`。
3. 复制 `article-detail.html`，替换标题、摘要、日期、阅读时间、正文和相关文章。
4. 同步更新 `<title>`、description、Open Graph、canonical 和 `sitemap.xml`。

## 替换图片与小球素材

- 作品封面推荐 1600×1200（4:3）；文章横图推荐 1600×900（16:9）；Open Graph 推荐 1200×630。
- 优先导出 WebP，普通展示图建议控制在约 300KB 内；设置明确的 `width`、`height` 与 `alt`，首屏外图片加 `loading="lazy"`。
- 网页当前使用 `assets/images/pet/` 中的小球正式素材：主形象来自 `小球形象/基本主要IP形象`，互动状态来自 `小球形象/一些表情包`。
- 更换动作素材时必须保留：矮胖蓝黑主体、大小不一的极简白眼，以及总数恰好两个、与身体分离的短小球状附肢；不要擅自增加固定嘴部或新肢体。
- `assets/js/pet.js` 中的 `conditionImages` 与 `actionImages` 分别控制状态图和互动反馈图；素材不足时复用现有主体并使用轻微位移、纵向压扁或旋转动画。

## 小球存档

- 键名：`zerohey_pet_state_v1`。
- 字段：版本、名字、创建/访问/结算时间、饱食、心情、精力、清洁、互动次数。
- 离线状态最多结算 24 小时；小球不会死亡或永久离开。
- 页面“重新开始”只删除这一键，不会调用 `localStorage.clear()`。
- 手动重置：浏览器开发者工具 → Application/存储 → Local Storage → 删除 `zerohey_pet_state_v1`。
- 存储不可用时，互动仍会在当前页面工作，并显示无法保存提示。

## GitHub Pages 发布

1. 登录 GitHub 并创建公开仓库。若希望使用根地址，可命名为 `<GitHub用户名>.github.io`。
2. 将本项目全部文件提交到 `main` 分支。
3. 打开仓库 `Settings → Pages`。
4. 发布来源选择“从分支部署”，分支选择 `main`，目录选择 `/ (root)`。
5. 保存并等待 GitHub 提供 Pages 地址。
6. 将所有 `https://YOUR-DOMAIN.example/` 替换为实际 Pages 地址，再检查 canonical、sitemap、Open Graph、邮箱、社交链接和全部占位内容。
7. 后续提交到 `main` 后，Pages 会自动更新。

项目全部使用相对资源路径，可部署到用户名根站或普通项目仓库的子路径。GitHub Pages 在中国大陆通常可直接访问，但速度和稳定性受网络环境影响，不能由本项目完全保证；未来可以在不重写前端的情况下迁移到其他静态托管。
